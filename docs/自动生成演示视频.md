# 从真实 ROS 2 运行自动生成视频

仓库包含独立的 `Record complete RViz demo` 工作流。它在 Ubuntu 22.04 / ROS 2 Humble 环境中启动 Xvfb 虚拟显示与真实 RViz，录制机械臂、工位、任务节点运行，再添加中文字幕。不是离线绘制的机器人动画。

## GitHub 上生成

进入仓库 Actions，选择 `Record complete RViz demo`，点击 Run workflow，使用 `main`。成功后在该次运行底部下载 `a2-complete-video`。其中包括：

- `A2完整演示.mp4`：约 2–3 分钟，正常完整循环、最终结果、加工超时、复位和来源说明。
- `normal-*.png`、`timeout-*.png`：实际 RViz 截图，适合填入 PPT。
- `video_manifest.json`：实际视频时长、各阶段出现时间与真实任务结果。
- `normal/`、`timeout/`：原始录屏、CSV、JSON、启动和录制日志。

工作流失败时同样尽可能保存材料。只有生成成功且经过画面检查的 MP4 才能作为演示视频。artifact 是临时存储，请下载保存；不要只给教师一个会过期的 Actions artifact 链接。

## Ubuntu 本地生成

已构建项目后安装可选录制依赖：

```bash
sudo apt install -y xvfb xauth openbox wmctrl imagemagick ffmpeg fonts-noto-cjk libgl1-mesa-dri
cd ~/a2_ws
bash scripts/capture_video.sh
```

结果在 `results/media/`。采用域 86、虚拟显示与软件渲染，不操作默认域中的手动演示。不要同时运行另一组域 86 的节点。输出为 1440×900、20 fps、H.264 MP4，实时 1×，无配音，已加入中文字幕。视频中正常过程保持连续，异常使用另一次启动的故障配置。

最后 12 秒使用最终成功截图说明自主开发和复用来源。异常段取消加工后展示复位；`stall` 是启动参数，复位不会改变它，恢复正常加工需要重新启动正常配置。真实小组姓名和个人贡献仍需按实际情况添加，PPT 姓名不能由工具虚构。

如果教学设备图形驱动或显示比例与云端不同，使用 `docs/视频录制脚本.md` 在实际 Ubuntu 桌面手动录制也可以。演示视频并不替代老师现场要求的实际运行。
