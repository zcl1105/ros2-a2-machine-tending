# 2–3 分钟视频：完整任务与一次异常

## 课程视频要求对应

截图要求：说明任务起点与目标；展示一次连续的完整运行；呈现关键状态和最终结果；补充一次条件变化或失败处理；加速片段注明倍速。视频不是安装教程，也不能用几个孤立动作替代完整循环。

建议总长 **2 分 30 秒左右**，1920×1080，30 fps，录制 Ubuntu 桌面。屏幕主体为 RViz，保留状态 HUD；关键服务指令可放在右下角终端。系统来源与小组姓名在封面或片尾注明。使用系统已有录屏工具即可；录制后检查文字大小和声音，不把未运行的场景包装成真实结果。

## 录制前

1. 在 Ubuntu 完成 `bash scripts/build.sh` 和 `bash scripts/integration.sh`。
2. 使用 `ros2 launch a2_demo demo.launch.py motion_seconds:=1.8 process_seconds:=7.0`。
3. 确认 RViz 的 RobotModel、MarkerArray、TF 无报错，能看到料盘、工位、毛坯、机械臂和 HUD。必要时转动相机，避免 HUD 遮挡机械臂；保持文字可读。
4. 先试运行一次，确认 JSON 成功结果。复位，等 `IDLE`、橙色毛坯恢复、夹爪打开、机械臂归位后，再开始正式录屏。
5. 可在第三个终端运行 `bash scripts/record_bag.sh` 保存同步 ROS 数据。正式视频仍需屏幕录制。

完整正常段预留约 50 秒，以实际运行时长为准。**完整正常段不切掉 WAIT_PROCESS，也不剪掉下料、回料盘或归位。** 若为满足总时长加速，保留连贯画面，并全程显示“2× / 4×”。不能把录制和剪辑计划写成已经完成的视频结果。

## 正常段终端命令

```bash
cd ~/a2_ws
source /opt/ros/humble/setup.bash
source install/setup.bash
ros2 service call /a2/task/start std_srvs/srv/Trigger '{}'
```

等待 `COMPLETE`。HUD 应显示 `Completed 1/1`、`Part TRAY`、`Part PROCESSED`、`Gripper OPEN`。打开结果：

```bash
ls -t results/*.json | head -n 1 | xargs cat
```

## 超时异常段

关闭正常 launch，再启动：

```bash
ros2 launch a2_demo demo.launch.py motion_seconds:=0.7 \
  stall:=true process_timeout:=6.0
```

调用 start，保留从上料、退出工位、开始加工、等待、超时到 `FAILED` 的画面。关键结果为 `WAIT_PROCESS timeout`、`Completed 0/1`。工位由中止命令进入 `FAULT`。等待机械臂停止后调用：

```bash
ros2 service call /a2/task/reset std_srvs/srv/Trigger '{}'
```

显示 `IDLE`、毛坯恢复、机械臂归位。`stall:=true` 是本次 launch 参数，复位不会关闭故障注入；要恢复正常加工，关闭并以正常参数重新启动。此点在汇报问答中要说明。

## 可替换的条件变化段

如果更偏好“工位占用后恢复”，使用正常 launch，先注入 `BUSY_ON`，再启动任务；让 `WAIT_READY` 持续约 5 秒，然后 `BUSY_OFF`。保持画面展示从等待到动作开始，并说明没有向占用工位强制上料。该段也可以作为额外演示，但不能替代正常完整循环。

## 交片检查

- 起点、目标、输入和成功条件明确。
- 正常循环连续：取料、上料、退避、加工、下料、回料盘、归位齐全。
- 关键状态文字和加工等待可读，最终结果可见。
- 至少一次条件变化或失败处理，有异常原因和结果记录。
- 所有加速片段标注倍速，录屏没有用预制动画代替实际运行。
- PPT 与视频中的平台、节点名、结果和源码一致；最终填写真实组员与贡献。
